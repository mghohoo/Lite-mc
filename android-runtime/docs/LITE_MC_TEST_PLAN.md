# Lite-MC Android 验证计划

范围是本目录中的 Android 产品，不是旁边 `android/` 中的早期骨架。Lite-MC 自有首页、账号、版本、Mod、皮肤及设置；Android JVM / 图形 / 游戏输入运行层保留第三方来源说明。

**验收等级必须分别记录。** 静态检查通过不等于安全审计通过；APK 能编译不等于能打开；首页能打开不等于 Minecraft 能进入世界。没有执行的项目记为「未测」或「阻塞」，不能记为通过。

## 环境与留证

- 每轮记录 Git 提交或工作区差异、APK SHA-256、版本号、签名证书指纹、Android 版本、ABI、WebView 版本、GPU 和设备型号。
- API 34 x86_64 模拟器用于首页、旋转、安装流程和受支持运行时的初步检查。ARM64 真机用于 JVM、图形兼容、游戏触控、后台恢复、热启动速度、发热与内存验收。模拟器结果不能替代真机结果。
- 测试账号由测试者本人在系统浏览器完成授权。不收集密码；截图遮盖邮箱、设备码；报告、日志、屏幕录像、版本库不得包含 access token、refresh token、CurseForge API key 或未经脱敏的认证响应。
- 不重置用户设备、不清除用户世界、不删除账号/实例，破坏性案例仅在明确标记的专用测试实例与测试账号上执行。安装不同证书 APK 前不自动卸载原应用。
- 每个用例至少留「环境、操作、预期、实际、通过/失败/未测、证据路径」。截图只能证明画面，启动结果还应有游戏日志与实际操作证据。

## 可重复自动检查

在 `D:\mc-lite\android-runtime` 中执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-lite-mobile.ps1

node .\tests\mobile-ui-regression.mjs
node .\tests\downloader-regression.mjs
node .\tests\progresskeeper-regression.mjs

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-lite-mobile.ps1 `
  -Build -RunUnitTests -JavaHome 'C:\Program Files\OpenJDK\jdk-22.0.2'

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-lite-mobile.ps1 `
  -ApkPath '.\app_pojavlauncher\build\outputs\apk\debug\app_pojavlauncher-debug.apk' `
  -DeviceSerial 'emulator-5554'
```

最后一条中的序列号必须替换为 FCCM 实际提供的在线设备。脚本不会启动/停止模拟器、安装应用、修改设备设置或主动打开应用。设备检查要求测试者已打开自己的 Lite-MC 首页。默认仅静态检查，缺模块时返回退出码 1；未选择的构建/设备项目明确显示 SKIP。JavaScript 使用 `node --check`，只检查语法，不能证明旧 WebView 兼容。

脚本检查 Lite-MC 必需模块、唯一入口、保留许可证、备份配置、WebView 本地来源/导航保护/CSP、Keystore 加密标记、明显凭据日志模式与两个 Mod 提供商的存在。正则标记不是实现正确性的证明；安全逻辑必须人工审阅并执行恶意输入测试。可选构建只执行 `assembleDebug` 和已存在的 `MioLibPatcher:test`，不虚构目前不存在的 app 单元/仪器测试。APK 验签只证明签名有效，不能证明发布私钥属于本项目。

当前基线（本计划首次创建时）：`app_pojavlauncher/src` 只有 `main`，没有自有 app 测试套件；`MioLibPatcher` 存在 JUnit 测试。旧重命名 APK 不作为新产品验收通过证据。后续应补充 bridge 参数校验、路径约束、下载校验、账号状态机的 JVM 或 Android 仪器测试。

现已补充独立离线回归入口：`mobile-ui-regression.mjs` 在最小 DOM/Canvas 模型里执行真实的 `app.js`/`skin.js`，检查翻译不删除控件、版本选择/安装按钮、账号与 Mod 按钮、桥接 action 对应、文本注入处理、Steve/Alex 手臂宽度与小幅动作。它不模拟真实 WebView 布局/渲染，不调用实际服务或微软认证。`downloader-regression.mjs` 以 JVM 编译真实下载器并使用 Android/网络 test doubles，覆盖完整缓存零网络、缺文件/断网、继承、取消、必需库失败与临时文件；它不会读写用户 Minecraft 数据。

`progresskeeper-regression.mjs` 直接编译真实的 ProgressKeeper 与三个无 Android 依赖的类型，在独立临时目录中验证 0 任务立即回调、完成后自移除、32 个等待者、监听器移除、回调重入/抛错及 1,000 轮注册与完成竞态。它不使用 Gradle，不把并发测试次数作为 Android 运行验证。脚本退出码非 0 表示编译或回归失败。

### 2026-09-17 Tcm 工作区回归记录

- 产品静态门槛：22 PASS，0 FAIL，3 SKIP（未由 Tcm 执行 Gradle、APK 验签、adb 检查）。
- 真实前端 JS 的 DOM/契约回归：16/16。此前发现并由 root 修复了翻译删除版本选择器、缺少 `skin.read`、按钮比例未返回以及官方 Alex 模型被本地 Steve 默认值覆盖。
- 真实下载器 + Android/网络替身回归：14/14。
- 真实 ProgressKeeper JVM 回归：9/9；1,000 轮并发注册/完成产生恰好 1,000 次回调，结束时 0 个任务和 0 个遗留等待监听器。测试促使 root 修复回调重入重复触发、异常监听泄漏以及嵌套完成时旧快照重复投递。
- 以上为源码工作区结果，不绑定某个 APK；APK 仍需 root/FCCM 记录构建、签名及哈希。没有可用模拟器/真机证据时，不应将 Android 启动、真实 OAuth、真实 Mod 下载或游戏进入世界记作通过。

## 发布门槛

1. 所有 P0：自己的入口可启动、离线原版实际进入世界、无明文凭据、无任意文件写入、无任意远程桥接执行，必须通过。
2. 所有对外承诺功能逐项有动态证据；微软授权、CurseForge key、ARM64 真机等前提缺失必须在交付说明中写明未测或限制。
3. FCCM 独立复核 Tcm 的证据，不仅重复静态脚本。Dcm 修复后必须重新运行失败案例及邻近回归。
4. 保存版本与 APK 哈希，区分 debug 验证包和正式发布包；不得用旧重命名 APK 的历史编译成功替代本轮验证。
